# Hybrid UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve one React web UI from a loopback server inside the Swift app, shown in native windows and in the browser, replacing the SwiftUI Sessions, Settings and live windows with the signal-room design.

**Architecture:** A Hummingbird 2 server inside the app binds `127.0.0.1:<random port>`, guarded by Host/Origin checks and a one-time-token → cookie login. Routes talk to an `AppBackend` protocol (AppModel in production, a fake in tests). A React + Vite + TypeScript app is built to static files bundled in the app; `WKWebView` windows, a floating `NSPanel` and the user's browser all load it. Live state flows over one SSE stream.

**Tech Stack:** Swift 5 language mode on the Swift 6.2 toolchain (Xcode 26), Hummingbird 2 + HummingbirdTesting, WebKit, GRDB; React 18 + Vite + TypeScript, Vitest, Playwright; fonts from `@fontsource/*` (OFL).

**Spec:** `docs/superpowers/specs/2026-11-26-hybrid-ui-design.md` (visual reference: the canvas linked there; local copies in `.superpowers/design/project/*.dc.html`).

## Global Constraints

- macOS 14.2+; the server binds `127.0.0.1` only; LAN access is out of scope.
- API keys are write-only through the API (never returned, only `"set": true|false`).
- `python-worker` is out of scope; capture code (`Sources/Capture/`) is not modified.
- The canvas is a visual reference; behaviour comes from the spec.
- Fonts are bundled, never fetched; no runtime network for UI assets.
- Tests use fakes: no real network, recordings, Keychain or sockets (except one Playwright smoke against a fixture server). `memory: ci-test-constraints` applies.
- Old SwiftUI views are deleted only after their web replacement reaches parity (spec Goal 5).

## Review Focus

1. A request from another site (cross-origin `Origin`) or a DNS-rebinding `Host` must get 403 and no data. Test in Task 2.
2. Audio seeking with odd `Range` headers (open-ended, suffix, past end) must answer 206/416 correctly without loading the whole file into memory. Test in Task 5.
3. An SSE client that disconnects (tab closed, Mac sleeps) must not leak a subscriber; reconnects resume and the UI shows a "reconnecting" state. Test in Task 8.
4. The same data edited from both hosts at once (rename a speaker in the browser while the archive window is open) must show up in both via events; last write wins. Test in Task 8.
5. After an app restart, an old browser tab gets 401 and shows "Open CallCapture from the menu bar to sign in again" instead of a broken page. Tests in Tasks 2 and 6.
